# ADR 0012：音乐库索引与歌单使用 SQLite

日期：2026-10-12。用户要求完整迁移音乐库索引并更新为 0.5.2，不做存储方案性能对比。保持 dev、OpenGL 与现有播放内核；本轮没有提交 / master 合入 / 推送授权。

## 决定

在应用磁盘服务下新增薄的 MusicStore，集中管理 SQL、事务、原始路径与 schema，不引入 ORM、数据库服务器、第二套运行时或通用插件。player-core 保留纯数据与业务规则，不依赖 rusqlite。固定 [rusqlite 0.40.2](https://docs.rs/rusqlite/0.40.2/rusqlite/)，关闭默认 features，仅开启 bundled；libsqlite3-sys 0.38.2 内置 SQLite 3.53.2，静态链接，不依赖用户 PATH 上的 SQLite DLL 或系统 SQLite。

数据库跟随设置路径：settings.json 对应 settings.library.sqlite3，YYPLAYER_CONFIG 的独立配置也使用对应独立库。音乐目录 / 单独文件 / 排除项、歌曲标签索引、歌单与有序成员、我喜欢及歌单 ID 序列进入关系表。歌曲路径为带平台标识的 BLOB，Windows 保存原始 UTF-16LE，Unix 保存原始字节；显示文本不作为身份。歌曲 ID 是 SQLite 稳定整数，歌单成员引用它，歌单位置另存。索引含歌手键与歌手 / 专辑联合键，不把不同歌手的同名专辑合并。

应用设置仍为 JSON，格式版本升级为 2，新的保存文件移除 library / playlists；可继续读取版本 1。music_order / video_order 等播放偏好仍随设置保存，音乐 / 视频队列仍是独立内存会话。视频库沿用独立 JSON 索引，本轮不改变其持久化范围。

## 迁移与恢复

Persistence worker 先打开 / 迁移数据库，成功后通过有界消息投递目录和歌单；controller 再启动音乐扫描服务。首次在一个 SQLite 事务内建立 schema、导入旧音乐索引 / 目录 / 歌单，保留 settings.library.json，迁移前保存 settings.pre-sqlite.json 的原始字节。数据库 application_id / user_version 独立于设置和应用版本；后续启动以数据库为准，不反复导入旧 JSON。

移除歌曲 / 目录使相应索引退出当前库，不删除磁盘文件，也不删除歌单引用的歌曲记录；未索引 / 失联成员保留。扫描取消 / 无效批次通过事务回滚保留上一次提交。损坏、未知版本 / 类型、只读、忙与无效路径分别返回可见错误，原数据库不自动删除或重建；恢复文件 / 权限后可重扫重试。设置已为版本 2 而库缺失时显式报错，不以空歌单覆盖。

扫描按路径 UPSERT，仅变更的标签 / 索引状态更新歌曲记录；移除项退出当前索引。歌单重命名保留成员行，成员编辑只替换对应歌单的有序关联，删除仅影响该歌单关联。标签读取仍沿用现有扫描器，本轮不把数据库迁移称为文件标签增量扫描。

所有 SQLite 调用留在后台磁盘服务，连接由相应 worker 独占。新库使用 SQLite 默认回滚日志，2 秒 busy timeout，有界命令 / 回复与扫描 generation 保留；退出时确保最新设置快照进入保存队列并排空回复。初始化完成前的保存请求保留数据库已有音乐数据，避免启动 / 退出竞态清空歌单。数据库音乐事务和 JSON 设置文件是两个独立提交；若 JSON 文件替换失败，明确提示音乐库已提交、应用设置未保存。

启动时通过文件对话框 / 拖入到达的音乐导入，在数据库就绪前暂存在遵守目录 / 文件上限的会话请求中，成功初始化后合并应用；不以空初始化状态丢弃导入。数据库不可恢复时仍保留原持久化数据，未完成导入只在本次会话等待重试。

首次成功加载的音乐配置作为当前会话的编辑基础；后续扫描写库失败不会把它降为未初始化状态，也不会在保存 / 退出时用旧数据库快照替换已接受的编辑。原位重试重新打开连接，保留本次会话的目录 / 歌单编辑并重新保存；如需以其他数据库备份替换整个音乐库，应退出后恢复文件再启动。

## 验证与边界

测试关注 JSON 导入 / 备份 / 幂等、目录 / 歌单顺序和我喜欢、稳定 ID、移除 / 失联、取消 / 无效批次回滚、忙 / 损坏 / 未来版本、原始路径、初始化 / 退出和实际 Slint 分类 / 批量播放 / 重启。性能对比按用户要求省略。

当前音乐库与单队列仍限 20000 首，歌单 128 个 / 合计 20000 成员；不因更换存储擅自扩容。旧 JSON 索引导入仍限 32MB，应用设置仍限 2MB，音乐歌单不再占该 JSON 配额。UI 继续按 revision 缓存索引快照并在内存筛选 / 分组，未引入数据库分页查询、全文搜索或实时目录监听。文件改名 / 移动仍需重新定位，不从稳定 ID 推断自动追踪。Linux / macOS 的本轮编译与真机资格单独记录。

结果与限制见 [迁移验收](../validation/sqlite-music-library.md)和 [STATUS](../STATUS.md)。
